# HR 201 File & Employee Management — GDS HR

The HR 201 modules extend the existing GDS HR application (same server, login, database, attendance, leave,
payroll and deductions). Nothing was moved into a separate system.

## Run and deploy

| Task | Command |
| --- | --- |
| Run locally (port 3400) | `npm run hr:dev` |
| Run the public site | `HR_ORIGIN=https://hr.blkstone.site node hr/src/server.mjs` behind the `gds-hr` Cloudflare tunnel |
| Preview with sample data (port 3401) | `node hr/scripts/preview-roster.mjs` |
| Tests | `npm run hr:test` |
| Lint | `node node_modules/eslint/bin/eslint.js hr --max-warnings=0` |

Database: `hr/data/hr.sqlite` (git-ignored, private). New tables are created automatically on start
(`CREATE TABLE IF NOT EXISTS`); existing data is not changed.

**Backup and recovery.** Before upgrades run
`node -e "const {DatabaseSync}=require('node:sqlite');new DatabaseSync('hr/data/hr.sqlite').exec(\"VACUUM INTO 'hr/data/backup-'+Date.now()+'.sqlite'\")"`.
To restore, stop the server and copy a backup over `hr.sqlite`. Keep copies off this computer as well.

## Modules

| Module | Where | Notes |
| --- | --- | --- |
| Dashboard | Dashboard | All figures computed from records; every card opens the matching list |
| Employee 201 Files | Employee 201 Files | Directory with search, filters, sorting, pagination; Add/Edit employee; archive/restore |
| Employee profile | Click a name | Overview, Personal, Employment, 201 documents, Memos, Trainings, Activity; “Attendance, leave & pay” opens the existing pay profile |
| 201 documents | Profile → 201 documents | Checklist from Settings; upload, preview, download, review, replace (versioned), Not Applicable |
| Data sheets | Employee portal → My data sheet; HR → Data Sheet Submissions | Draft → Submitted → Under review → Approved / Returned / Rejected |
| Memos | Memos; employee portal → Memos | Draft, issue to all / departments / employees, revise (new version), archive, acknowledgement of receipt |
| Trainings | Trainings (list and calendar); employee portal → Trainings | Registration, attendance and completion recorded separately; certificates filed as 201 documents |
| Reports | Reports | Master list, department and classification summaries, new hires, document gaps and completion, memo acknowledgements, training participation, review schedule |
| Settings | Settings (System Administrator) | Branding and theme, departments, positions, classifications, employee number format, document requirements, upload limits, reminders, optional fields, retention |

## Data model (SQLite)

| Table | Holds |
| --- | --- |
| `state` (JSON) | Employee master (`id` = stable internal ID, `employeeNumber` = optional displayed number, `archived`), attendance, leave, payroll |
| `employee_profiles` | Per-employee sections: personal, employment (position, classification, status, contract / probation / review dates), emergency, government (restricted) |
| `employee_documents` | Files (BLOB) + metadata. 201 documents: requirementId, version, replaces, reviewStatus, reviewer, issue/expiry dates, restricted |
| `requirement_overrides` | Not Applicable decisions per employee and requirement, with reason |
| `hr_settings`, `hr_counters` | Settings JSON; employee-number and memo-reference sequences |
| `memos`, `memo_assignments`, `memo_attachments` | Memo with issued versions; one assignment row per version × employee with acknowledgement time; attachments |
| `trainings`, `training_participants` | Sessions; per-participant registration, attendance, completion, certificate document |
| `datasheets` | Employee submissions with status and history |
| `audit` | All changes, approvals, exports and document views |

Employee numbers are allocated inside a database write transaction, so simultaneous submissions cannot receive the
same number. Changing the displayed number never changes the internal ID that other records use.

## Roles and permissions (enforced on the server)

| Role | Employees | Gov. IDs | Documents | Restricted docs | Data sheets | Memos | Trainings | Reports | Settings |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| System Administrator (`admin`) | Manage, archive | Full | Upload, review | Yes | Approve | Draft, issue | Manage | All | Yes |
| HR Manager (`hr`) | Manage, archive | Full | Upload, review | Yes | Approve | Draft, issue | Manage | All HR | — |
| HR Staff (`hr_staff`) | Add, edit | Masked | Upload, review | No | Review, return | Draft only | Manage | HR | — |
| Department Manager (`dept_manager`) | View own department | Hidden | Progress only | No | — | View team status | View team | Team | — |
| Management (`viewer`) | View | Hidden | Progress only | No | — | View | View | Summaries | — |
| Payroll (`payroll`) | View | Full | — | No | — | — | — | Pay | — |
| Employee (`employee`) | Own record | Own (not shown back) | Own uploads | No | Own | Read, acknowledge | Confirm / decline | Own | — |

Department Manager accounts are linked to the manager's own employee record; their team is that employee's department.

## Not configured / limits

- **Email** for reminders and memos is not sent (no mail service is set up for these). Notices appear in the
  dashboard, the 🔔 bell and the employee portal.
- **Data sheet invitations** for people without an employee login are not implemented; create the employee and an
  employee login first.
- **Scheduled reminders** run when pages are opened (dashboard, bell); there is no background job.
- The software supports HR record-keeping; it does not guarantee legal or regulatory compliance.

## Testing checklist

Automated (`hr/tests/hr201.test.mjs`): add employee + persistence after reopening + duplicate warning; upload and
verify updates completion and dashboard; restricted documents and other departments blocked, including direct
requests; data sheet approval updates the same record; memo recipients and acknowledgement counts; training
attendance/completion in profile and reports; settings permissions and classifications.

Manual: sign in on a phone and a desktop; add an employee; upload, review, replace and download a document; issue a
memo and acknowledge it as the employee; assign a training and record attendance; submit and approve a data sheet;
download each report as Excel and PDF with filters; sign in as HR Staff and confirm Settings and payroll are hidden.
